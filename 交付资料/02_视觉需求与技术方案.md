# AGV 视觉需求与技术方案

版本：资料整理版 v1.0；日期：2026-11-11；项目包：pkg5_260728；负责人、客户正式项目名称：待补充。

## 1. 任务与范围

本项目为眼在手上的视觉定位与六自由度补偿：通过机器人末端相机观察标定板/工位目标，在 AGV 到位后计算机器人法兰的补偿。提供在线拍照、完整 3D 手眼标定、工位基准采集、二次补偿及光源控制 HTTP 接口。

当前在线配置为海康二维彩色成像，`enable_depth=false`。使用标记几何与 PnP 求取三维位姿，不依赖深度图。支持其他厂商的代码不表示现场同时使用这些相机。

当前工位基准和补偿选择 `cross_calibration.target_type=charuco`，不是 README 早期示例中的单 ArUco 方案。工位数量、AGV 数量、最终工位编号及作业对象由项目负责人确认。

## 2. 指标与适用限制

| 项目 | 已知内容 | 交付状态 |
|---|---|---|
| 位置精度、角度精度、重复性 | 未发现可直接作为本版本签字验收依据的正式指标 | 待客户/工艺确认 |
| 在线补偿限制 | 平移 0.05 m；旋转 0.5 rad（约 28.65°） | 当前 YAML 软件限制，不是精度承诺或运动安全证明 |
| 取图超时 | 5000 ms | 配置值 |
| 开灯等待 | 1000 ms；保持常亮时不逐张重复等待 | 配置与代码行为，完整节拍待实测 |
| 工作距离、视野、停靠允许偏差 | 未冻结 | 结合安装尺寸、完整板可见范围和机器人工作空间核定 |

适用前提：相机与法兰刚性连接，标定时标定板在机器人基座下固定；基准采集与补偿期间工位目标固定，目标尺寸和字典正确，图像清晰、无明显遮挡与反光。修改焦距、分辨率、相机安装关系或工位板后，应按标定文档复核。

## 3. 系统组成与流程

软件后端通过 HTTP 调用视觉服务；视觉服务通过海康 MVS 取图，通过 Nodka 桥接库控制光源。生产机器人/AGV 调度由后端及控制系统负责。`auto_handeye` 是另一个通过 Modbus TCP 调度采样的工具入口，不能默认等同于生产 HTTP 链路。

完整业务顺序：

1. 后端确认 AGV 到位、机器人到观察位且停稳，获取同一时刻对应的法兰位姿。
2. 后端调用工位基准或二次补偿接口；服务开灯、等待、触发采图（保持模式按代码处理）。
3. 识别 ChArUco，结合内参、畸变及手眼矩阵计算补偿。
4. 服务检查平移/旋转阈值并返回业务状态。
5. 后端按本版本接口的差值语义处理结果，机器人控制端完成可达性、限位、碰撞及轨迹安全检查后执行。
6. 控制端确认执行完成，必要时重新拍照复核；独立量具验证实际工艺位置。

## 4. 职责

| 责任方 | 工作 |
|---|---|
| 视觉 | 成像、标记识别、内参/手眼求解、基准数据输出、补偿计算、参数和日志归档 |
| Java 后端 | 到位后触发、绑定并保存完整 handeye/reference 数据、提供当前法兰位姿、管理请求与工位、处理响应和重复请求 |
| PLC/机器人 | 运动执行、状态反馈、联锁、安全限制、异常停机和复位 |
| AGV/现场 | 导航停靠、安装稳定性、目标标记维护、网络供电与现场工况保障 |
| 项目负责人/验收方 | 确认精度与节拍标准、设备清单、未完成项和最终签收 |

视觉 HTTP 接口未校验 `ready=true` 等到位字段；不能把健康返回或拍照成功解释为运动已安全完成。视觉补偿不提供通用轨迹迁移或碰撞检测能力。
