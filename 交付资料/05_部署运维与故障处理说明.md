## 3. 现场启动和维护命令

在核实的项目根目录执行，硬件依赖完成后再启动：

```bash
# 仅验证 Compose 展开结果
docker compose -f docker-compose.online.yml config
# 查看运行状态和日志
docker compose -f docker-compose.online.yml ps
docker compose -f docker-compose.online.yml logs --tail=100
# 首次构建/代码或依赖更新
docker compose -f docker-compose.online.yml up -d --build agv-vision-pkg5-online
# 挂载 YAML 内容修改后重启
docker compose -f docker-compose.online.yml restart agv-vision-pkg5-online
# 停止/恢复已有容器
docker compose -f docker-compose.online.yml stop agv-vision-pkg5-online
docker compose -f docker-compose.online.yml start agv-vision-pkg5-online
# 服务存活检查
curl http://127.0.0.1:8088/api/v1/health
```

环境变量、挂载和设备映射变化要重新创建容器，单纯 restart 不会应用 Compose 定义变化：

```bash
docker compose -f docker-compose.online.yml up -d --no-build --force-recreate agv-vision-pkg5-online
```

确认 Docker daemon 已开机启用并在运行，检查容器重启策略。unless-stopped 下手动停止的容器可能在重启后继续保持停止；最终需实际重启工控机验证。当前配置未定义 healthcheck，不能预期容器自动给出 healthy 状态。

非 Docker 方式按原现场环境安装依赖和厂商 SDK 后，从项目根目录执行 `python -m agv_vision.main --config agv_vision/config/settings_online.yaml serve`。禁止多个进程同时占用同一相机/光源。

## 6. 故障处理

| 现象 | 优先检查 | 恢复验证 |
|---|---|---|
| 后端访问失败 | 工控机 IP/8088、路由防火墙、是否误用后端自身 127.0.0.1 | 后端请求是否真正进入视觉日志 |
| 相机连接失败 | 192.168.1.118、网卡网段、相机占用、MvImport/MVS .so、架构 | 实际单张采图 |
| 光源库找不到 | 三个 Nodka 文件、动态库依赖、设备映射与权限 | 控制器读回+实物亮灭 |
| 全黑/过曝/模糊 | 10 ms 曝光、50 亮度、光圈/焦距、停稳及触发时序 | 保存原图并检查角点 |
| 取图超时/faulted | 相机/光源连接、触发、新帧；先检查硬件 | 关闭重开后实际采图，不能无限重试 |
| ChArUco 失败 | 手眼/工位两套板型、字典、ID、板尺寸、视野和清晰度 | 单图检查与原图 |
| 补偿超限 | 位姿单位/法兰TCP、当前工位基准、标定版本、真实停靠偏差 | 核对原因后受控复核，不直接放宽阈值 |
| PLC 超时 | 链路、地址、握手、当前执行状态 | 重连读回，结果未知时不重复下发动作 |
| 图片无法显示 | 服务端写入路径、宿主机映射、后端访问方式 | 文件存在且后端可实际读取 |

验收分级：HTTP 存活 → 光源读回/亮灭 → 真实新图 → 标记识别/补偿 → PLC/机器人通信 → 实际动作与独立测量。各级分别记录证据。
