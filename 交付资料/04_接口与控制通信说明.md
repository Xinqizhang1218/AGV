## 1. 概述

视觉负责采图、标定和补偿计算；Java 负责到位触发、保存完整标定/基准数据、当前法兰位姿输入和结果执行管理。下面按当前 `agv_vision/api/app.py` 填写。历史 README 或接口文档与代码冲突的地方已明确指出，不修改现有 API。

**关键差异：二次补偿响应 `targetFlangePose` 当前是六轴差值。后端是否已按此接入待现场确认。**

## 2. 服务地址

项目根目录启动：

```bash
python -m agv_vision.main --config agv_vision/config/settings_online.yaml serve
```

监听 `0.0.0.0:8088`。后端 Base URL 为 `http://现场视觉工控机IP:8088`（IP 待确认）；127.0.0.1 仅用于同机访问。相机 IP 192.168.1.118 不是视觉 HTTP 地址。

## 3. 通用约定

POST 使用 `Content-Type: application/json`，建议 `Accept: application/json`。业务返回：

```json
{"code":0,"msg":"success","data":{},"timestamp":1794355200000}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| code | integer | 0 成功；400 为被捕获的业务失败 |
| msg | string | 结果说明/异常文字，不作为稳定枚举错误码 |
| data | object | 业务结果，失败通常为空对象 |
| timestamp | integer | Unix 毫秒，优先回显请求值 |

处理器正常返回和捕获异常返回通常为 HTTP 200；未捕获异常可能为 500；FastAPI 请求结构验证可能为 422。后端同时处理 HTTP 失败及 JSON code，不能只检查 HTTP 200。

推荐驼峰字段，部分字段支持下划线兼容别名。**本项目实际单位为 m、rad、px、ms；沿用既有合同，未套用通用模板中的 mm/deg。** 位姿旋转顺序 Rz*Ry*Rx。

## 4. 业务流程

Java 确认机器人/AGV 到位停稳 → 拍照与位姿配对 → eye_hand → 保存完整 data；工位示教 → cross_calibration → 保存完整 data；每次作业 → 读取当前法兰位姿 → secondary_compensation → 检查 code/超时/请求归属 → 按差值语义处理 → 控制端验证后执行。

源码没有以 ready/inPlace 字段校验到位；此条件由调用方保证。HTTP 服务不自动控制 AGV 或机器人到位。重复请求可能再次采图，不应假设 timestamp/taskId 提供去重保证。后端应串行管理同一工位作业、丢弃过期结果，动作状态未知时先核实再重试。

## 6. 接口详细定义

以下 JSON 是格式示例，路径和位姿不是现场运动指令；正式矩阵/角点必须使用已验证标定结果。

### 6.1 GET /api/v1/health

无 Query 参数。

```json
{"code":0,"msg":"success","data":{"ok":true,"mode":"online","config":"agv_vision/config/settings_online.yaml","service_port":8088},"timestamp":1794355200000}
```

data：ok 为 boolean；mode/config 为 string；service_port 为 integer。config 实际表示可为加载路径。此结果不执行真实取图、不验证 PLC/机器人，也不确认完整光源链路。

### 6.2 POST /api/v1/agv/photo

```json
{"timestamp":1794355200000,"data":{"imagePath":"/app/data/acceptance/p01.jpg"}}
```

data.imagePath：必填 string，视觉服务器可写路径，兼容 image_path。成功 data 为 `{"imagePath":"/app/data/acceptance/p01.jpg"}`。目录权限及容器/宿主机映射需确认；它不是自动生成的 HTTP 下载 URL。

### 6.3 POST /api/v1/agv/handeye_observation

```json
{"data":{"imagePath":"/app/data/acceptance/p01.jpg","sampleId":"p01"}}
```

imagePath 必填 string；sampleId 可选 string，缺省 preview。处理已保存图片，不新拍照。成功 data 包含 sampleId(string)、imagePath(string)、cornerCount(integer)、markerIds(integer[])。单图通过不能替代手眼求解或精度验证。

### 6.4 POST /api/v1/agv/eye_hand

```json
{"timestamp":1794355200000,"imagePointList":[{"sampleId":"p01","imagePath":"/app/data/acceptance/p01.jpg","x":0.2,"y":0.17,"z":0.35,"rx":0.0,"ry":0.0,"rz":0.0}]}
```

imagePointList：必填 object[]，上例只展示一条字段结构，实际至少 5 组；也兼容 data.imagePointList。每条 imagePath 为 string，XYZ/RPY 为 number（m/rad），sampleId 用于关联。要求多轴姿态且每帧图像与实际位姿一致。

成功 data 字段：

| 字段 | 类型/形状 | 单位/含义 |
|---|---|---|
| rmseM | number | 手眼一致性平移 RMSE，m |
| sampleCount | integer | 参与求解样本数 |
| pose3d.version | integer | 结构版本 |
| pose3d.cameraMatrix | number[3][3] | 相机内参，像素尺度 |
| pose3d.distCoeffs | number[] | 畸变系数 |
| pose3d.gTc | number[4][4] | 相机到末端变换，平移 m |

Java 原样保存整个 data，补偿时放入 data.handeye。接口不调用 backend.save_handeye；调试留档不能代替后端正式版本管理。

### 6.5 POST /api/v1/agv/cross_calibration

```json
{"data":{"stationId":"station_001","imagePath":"/app/data/acceptance/reference.jpg"}}
```

imagePath 必填 string；stationId 建议显式提供，代码兼容 station_id/sn 回退。此接口在线拍摄基准图。成功 data：stationId(string)、imagePath(string)、markerId(integer)、corners(object[])。当前 ChArUco 每个 corner 为 `{id: integer, x: number, y: number}`，坐标 px，不能删掉 id 或仅保留四角。

Java 原样保存整个 data，补偿时放入 data.reference。接口不调用 backend.save_reference。改变工位板或相机几何后重采基准。

### 6.6 POST /api/v1/agv/secondary_compensation

| 请求 data 字段 | 类型 | 要求 |
|---|---|---|
| stationId | string | 工位编号，建议必传 |
| taskId | string | 请求任务编号，可选；缺省按工位生成，不保证唯一/幂等 |
| imagePath | string | 必填，本次新拍图片保存路径 |
| currentFlangePose | object | 必填，x/y/z/rx/ry/rz 必须为有限 number |
| currentFlangePose.translationUnit | string | 缺省 m，只允许 m |
| currentFlangePose.rotationUnit | string | 缺省 rad，只允许 rad |
| handeye | object | 前述 eye_hand 完整 data |
| reference | object | 前述 cross_calibration 完整 data |

配套文件提供由历史 station_001 数据组成的 `secondary_compensation_历史格式示例.json`，仅供字段核对；其基准与当前板型不保证匹配，不可直接用于控制运动。

成功响应格式示例：

```json
{"code":0,"msg":"success","data":{"taskId":"example-only","targetFlangePose":{"x":0.001,"y":0.0,"z":0.0,"rx":0.0,"ry":0.0,"rz":0.0,"translationUnit":"m","rotationUnit":"rad"}},"timestamp":1794355200000}
```

**实现语义**：先内部计算绝对目标，再逐字段减去请求 currentFlangePose；角度差用 atan2(sin(delta),cos(delta)) 归一化。响应名仍为 targetFlangePose，但内容是上述差值。下游若需要绝对 XYZ/RPY，应结合同一请求位姿按约定重建；不应把此字段直接作为绝对运动目标，也不能当作任意坐标系的刚体增量矩阵。

调用后端必须确认使用的是这份源码语义；正式联调未完成前不认定生产接入通过。软件限制来自 compensation.max_translation_m=0.05 和 max_rotation_rad=0.5，超过阈值返回业务失败，不提供可执行结果。

### 6.7 POST /api/v1/agv/light/control

```json
{"data":{"action":"on"}}
```

action 必填 string，仅 on/off。成功返回 data={}，msg 为开灯成功/关灯成功。亮度/端口/通道通过配置管理，不在此接口调整。on 建立常亮保持；保持期间拍照后不自动关灯；off 释放保持并关灯。结束、取消或异常恢复须处理关灯及状态核实。

### 6.8 GET /api/v1/agv/light/status

无 Query 参数。成功 data：`{"state":"on","held":true}`；state 为 string，held 为 boolean。失败时业务 code=400，data 可能带故障状态快照。控制器读回与真实灯亮、图像亮度仍需分别验证。

## 7. 错误码与异常处理

业务 code=400 涵盖缺字段、图像读写失败、识别失败、标定失败、补偿超限和光源故障；源码没有独立稳定的细分数字错误码表。图像路径问题核对服务端权限；识别问题核对板型与清晰度；光源 faulted 后先检查硬件再关闭/重新打开或重启，不能无限自动重拍。

## 8. 调用示例与 PLC 控制

```bash
curl http://127.0.0.1:8088/api/v1/health
curl -X POST http://127.0.0.1:8088/api/v1/agv/photo -H 'Content-Type: application/json' -d '{"data":{"imagePath":"/app/data/acceptance/p01.jpg"}}'
```

采图会访问真实相机/光源，以上为现场操作说明，本次整理没有执行。

下表仅依据 `auto_handeye/robot_client.py` 的工具协议，不宣称是生产 PLC 最终签字点表。PLC IP 在 auto_handeye/config.yaml 中为空，端口 502。

| 地址 | 方向（相对工具） | 类型/含义 |
|---|---|---|
| D100–D111 | 读 | 实际 XYZ/RPY，6 个 float32，每值 2 words |
| D1020–D1031 | 写并读回 | 目标 XYZ/RPY，6 个 float32 |
| D1002 | 读写 | 1 启动/保持；0 释放；须现场确认单点语义 |
| D1012 | 读 | 到位状态，按 0/1 判断 |
| D1008、D1009、D1018、D1019 | 读 | 任一非零视为复位/暂停/报警/异常；具体逐点名称待 PLC 方确认 |

float32 打包：每寄存器高字节在前；双寄存器低 word 在前（代码先 >f 拆成 high/low，再写 low/high）。XYZ 为 m，角为 rad，地址按工具传入的数值，现场确认设备映射。

工具顺序：确认空闲/稳定 → 写目标并读回一致 → D1002=1 → 等待到位及稳定 → 采样 → D1002=0 → 确认释放。写超时是结果未知，不自动重试；退出关闭连接不是急停，不自动清 D1002。

ARCS IK 入口为可选，当前 mode=disabled、IP/robot_name 未填；端口 30004 只是待核实配置，不能作为当前机器人已连通证据。
