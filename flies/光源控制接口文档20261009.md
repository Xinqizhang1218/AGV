# 光源控制接口文档（20261009）

> 代码待实现。使用现有视觉服务地址；原有拍照、手眼及跨机台接口的请求和响应不改。

## 1. 开关灯

`POST /api/v1/agv/light/control`

请求头：`Content-Type: application/json`。

开灯并保持：
```json
{"data": {"action": "on"}}
```

关灯并释放保持：
```json
{"data": {"action": "off"}}
```

`action` 必填，仅支持 `on` / `off`。亮度、通道、串口沿用视觉配置。

## 2. 查询状态

`GET /api/v1/agv/light/status`

无需传参，只查询，不开关灯、不改变保持状态。

## 3. 返回结果

两个接口共用以下结构，示例为正常开灯保持：

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "state": "on",
    "held": true,
    "brightness": 50,
    "faulted": false,
    "faultMessage": null
  },
  "timestamp": 1791504000000
}
```

| 字段 | 说明 |
|---|---|
| `code` | `0` 成功，`400` 失败，原因见 `msg` |
| `state` | 控制器读回状态：`on` / `off` / `unknown`，不等同实际发光检测 |
| `held` | 是否保持常亮 |
| `brightness` | 亮度参数 0～100，无法确认时为 `null`；关灯后可保留亮度参数 |
| `faulted` | 是否有故障；为 `true` 时不能继续正常采图 |
| `faultMessage` | 故障说明，无故障为 `null` |
| `timestamp` | Unix 毫秒时间戳 |

正常关灯成功：`state=off`、`held=false`。参数错误时 `data` 可为空对象；通信失败返回未知状态和故障信息，不能当作已关灯。

业务响应使用 HTTP 200，Java 按 `code` 判断成败；未捕获异常使用 HTTP 500。

## 4. 调用规则

- **手眼采图：** 后端 `on` → 成功后逐点到位停稳、拍照 → 整组结束 `off`；取消或异常退出也要关灯。
- **未调用 on：** 视觉自动开灯 → 等待稳定 → 拍照 → 关灯，跨机台沿用此流程。
- **保持期间：** 拍照后不关灯；`off` 后下一次拍照恢复自动开关。
- **异常：** 控制或取图故障时取消保持并尝试关灯；超时、状态未知时先排查，不能盲目继续。

开关灯与曝光互斥；重复 on/off 不叠加保持次数。本版不设常亮超时，后端须主动关灯；再次调用 on 不自动清除故障。
