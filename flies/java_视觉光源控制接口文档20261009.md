|---|---|
| `POST /api/v1/agv/light/control` | 新增，控制光源开启或关闭 |
| `GET /api/v1/agv/light/status` | 新增，查询当前光源状态 |

# 二、光源控制接口

```http
POST /api/v1/agv/light/control
Content-Type: application/json
```

## 1. 开灯

请求：

```json
{
  "data": {
    "action": "on"
  }
}
```

成功响应：

```json
{
  "code": 0,
  "msg": "开灯成功",
  "data": {},
  "timestamp": 1791504000000
}
```

调用成功后，光源保持开启，后续拍照完成后不自动关灯。

---

## 2. 关灯

请求：

```json
{
  "data": {
    "action": "off"
  }
}
```

成功响应：

```json
{
  "code": 0,
  "msg": "关灯成功",
  "data": {},
  "timestamp": 1791504000000
}
```

调用成功后关闭光源，并取消保持状态；下一次拍照恢复自动开灯、拍照、关灯。

---

## 3. 返回约定

- `code=0`：操作成功。
- `code=400`：操作失败，具体原因放在 `msg`。
- `timestamp`：Unix 毫秒时间戳。

失败示例：

```json
{
  "code": 400,
  "msg": "光源通信失败，开关状态无法确认",
  "data": {},
  "timestamp": 1791504000000
}
```

业务响应使用 HTTP 200，Java 需判断响应体中的 `code`，不能仅依据 HTTP 状态判断成功；未捕获异常使用 HTTP 500。

# 三、光源状态接口

```http
GET /api/v1/agv/light/status
```

无请求体。

成功响应：

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "state": "on",
    "held": true
  },
  "timestamp": 1791504000000
}
```

| data 字段 | 说明 |
|---|---|
| `state` | 控制器读回状态：`on`、`off` 或 `unknown`|
| `held` | 当前是否处于常亮保持模式：true 表示拍照后不自动关灯；false 表示未保持，自动补光拍照结束后关灯。 |

该接口仅查询当前光源状态，不执行开灯、关灯，也不改变 `held` 状态。查询失败时 `held` 仍返回服务原有记录，下面示例假设原记录为 `true`。

如果控制器状态无法读取：

```json
{
  "code": 400,
  "msg": "光源状态查询失败：控制器读回失败",
  "data": {
    "state": "unknown",
    "held": true
  },
  "timestamp": 1791504000000
}
```

# 四、手眼标定由 Java 控制开关灯

**手眼标定采图前，必须由 Java 主动调用开灯接口，确认 `code=0` 后再开始采图。** Java 通过视觉接口控制光源，不直接操作光源串口。
