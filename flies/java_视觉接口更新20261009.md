
|---|---|

| `rx/ry/rz` | rad |

目标结构：

```json
{
  "code": 0,
  "msg": "手眼标定完成",
  "data": {
    "rmseM": 0.0004,
    "sampleCount": 12,
    "pose3d": {
      "version": 1,
      "cameraMatrix": [
        [1000.0, 0.0, 640.0],
        [0.0, 1000.0, 360.0],

      ],

        [1.0, 0.0, 0.0, 0.01],
        [0.0, 1.0, 0.0, 0.02],
        [0.0, 0.0, 1.0, 0.03],
        [0.0, 0.0, 0.0, 1.0]
      ]
    }
  },
  "timestamp": 1780000000000
}
```

### 字段说明表

| 当前字段 | 含义 |
|---|---|
| `rmseM` | 手眼标定的平移均方根误差，单位 m；数值越小，表示标定结果越稳定。 |

| `pose3d.cameraMatrix` | 相机内参矩阵。 |
| `pose3d.distCoeffs` | 相机畸变系数数组，用于修正镜头的径向和切向畸变。 |
| `pose3d.gTc` | 相机坐标系到机械臂末端坐标系的 4×4 齐次变换矩阵。 |

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "taskId": "task-001",
    "targetFlangePose": {

      "rz": -0.171,

    }
  },

}
```

### 字段说明表

| 当前字段 | 含义 |
|---|---|
| `taskId` | 请求中的任务编号。 |
| `targetFlangePose` | 视觉计算得到的完整目标末端位姿；这是 Java 下发给机械臂执行的数据。 |

```text
data.taskId
data.targetFlangePose
```

# 六、新增光源控制接口（待实现）

```http
POST /api/v1/agv/light/control
Content-Type: application/json
```

开灯并保持，或关灯并释放保持状态。前提是视觉光源控制已启用、控制器已连接且无未恢复故障。由视觉服务统一操作控制器，Java 不直接占用光源串口。

## 请求体

开灯：

```json
{
  "data": {
    "action": "on"
  }
}
```

关灯：

```json
{
  "data": {
    "action": "off"
  }
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `data.action` | string | 是 | 仅接受小写 `on` 或 `off` |
| `sn` | string | 否 | 设备或任务追踪标识；不作为光源独占凭证 |
| `timestamp` | long | 否 | Unix 毫秒时间戳；提供时响应原样回传，省略时由服务端生成 |

## 成功响应 `code=0`

开灯成功：

```json
{
  "code": 0,
  "msg": "光源已开启并保持",
  "data": {
    "state": "on",
    "held": true,
    "brightness": 50,
    "faulted": false,
    "faultMessage": null
  },
  "timestamp": 1791504000000
}
```

关灯成功：

```json
{
  "code": 0,
  "msg": "光源已关闭并释放保持状态",
  "data": {
    "state": "off",
    "held": false,
    "brightness": 50,
    "faulted": false,
    "faultMessage": null
  },
  "timestamp": 1791504000000
}
```

| data 字段 | 类型 | 说明 |
|---|---|---|
| `state` | string | 控制器读回状态：`on`、`off`；无法确认时为 `unknown` |
| `held` | boolean | 是否处于后端显式要求的保持状态；仅开灯确认成功后置为 `true` |
| `brightness` | integer / null | 控制器读回的亮度参数，范围 0～100；读回失败时为 `null`。关灯后该参数可以仍为 50，不代表灯亮 |
| `faulted` | boolean | 是否存在阻止正常光源拍照的故障；普通请求参数错误不应设置设备故障 |
| `faultMessage` | string / null | 故障说明；无故障为 `null` |

示例中的亮度 50 仅演示返回结构，实际取配置和控制器读回值。读回确认的是控制器参数，不等同于光学传感器确认实际发光。

## 失败响应 `code=400`

参数错误示例：

```json
{
  "code": 400,
  "msg": "data.action 仅支持 on 或 off",
  "data": {},
  "timestamp": 1791504000000
}
```

设备状态无法确认示例（已取消保持并尝试关灯，但关灯未获确认）：

```json
{
  "code": 400,
  "msg": "光源通信失败，控制器状态无法确认",
  "data": {
    "state": "unknown",
    "held": false,
    "brightness": null,
    "faulted": true,
    "faultMessage": "控制器读回失败，需检查连接并恢复"
  },
  "timestamp": 1791504000000
}
```

正常业务响应均使用 HTTP 200，Java 必须检查响应体 `code`；HTTP 500 留给未捕获异常。光源未启用、未连接或处于故障状态时返回业务失败，不得返回模拟开灯成功。

## 控制语义

- `on`：开灯、读回确认并等待配置的稳定时间后返回成功；后续拍照保持亮灯。重复 `on` 不叠加保持次数。
- `off`：释放保持状态并关灯，读回确认后返回成功。重复 `off` 不报“已经关闭”错误，但仍需确认控制器状态。
- `off` 不代表禁止自动补光。之后再调用拍照接口，视觉仍会自动开灯、拍照、关灯。
- 光源控制与完整曝光取图过程必须串行执行；曝光期间收到关灯请求，应等待本次取图结束再关灯。
- 光源保持状态属于当前服务控制的光源，不按 `sn` 分组。Java 应串行安排使用同一光源的任务，避免一项任务关闭另一项任务的灯。
- 开灯、取图或关灯发生设备异常时，取消保持、尝试关灯并记录故障；无法确认关灯时返回 `unknown`，不能把 `held=false` 当作实际已关灯。
- 普通 `on` 请求不能绕过故障恢复；查询成功也不自动清除已记录的采集故障。

# 七、新增光源状态接口（待实现）

```http
GET /api/v1/agv/light/status
```

查询当前控制器状态、保持状态及故障信息。无 Query 参数，无请求体；查询不主动开关灯、不改变保持状态。

## 成功响应 `code=0`

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "state": "on",
    "held": true,
    "brightness": 50,
    "faulted": false,
    "faultMessage": null
  },
  "timestamp": 1791504000000
}
```

data 字段定义与第六节相同。`state`、`brightness` 来自本次控制器读回；`held`、`faulted`、`faultMessage` 来自服务管理状态。响应时间戳由服务端生成。

查询成功只表示本次状态读取成功；若此前采集故障仍未恢复，可返回 `code=0` 且 `faulted=true`，Java 仍不得按可拍照处理。

## 失败响应 `code=400`

控制器读回失败时返回 `state=unknown`、`brightness=null`、`faulted=true` 及故障说明；`held` 返回服务当前记录的值，不因 GET 查询而改变。查询失败不应返回上一次的 `on` / `off` 冒充本次已确认状态。

```json
{
  "code": 400,
  "msg": "光源状态查询失败",
  "data": {
    "state": "unknown",
    "held": true,
    "brightness": null,
    "faulted": true,
    "faultMessage": "控制器读回失败"
  },
  "timestamp": 1791504000000
}
```

Java 无需将光源状态加入手眼、基准或补偿结果中持久化回传；需要时重新查询。状态仅反映查询时刻，不能替代拍照时的光源检查。

# 八、本次调用流程与实现边界

## 手眼标定：后端主动开灯保持

```text
GET /api/v1/health 确认服务可用
→ POST /api/v1/agv/light/control，action=on
→ 确认 code=0
→ 机器人逐点到位、停稳后调用原 photo 接口（请求、响应不改）
→ 每张图采集完成后保持亮灯
→ 整组采图完成后调用 light/control，action=off
→ 调用原 eye_hand 接口计算（请求、响应不改）
```

Java 在取消或异常退出时也应执行关灯清理。只需在采图阶段保持亮灯，计算阶段不需要。每次拍照仍由调用方保证机器人到位、停稳，光源接口不控制机器人运动。

## 后端不调用开灯 / 跨机台拍照

没有保持状态时，沿用“视觉自动开灯 → 等待稳定 → 触发取图 → 自动关灯”的流程；手眼采图、跨机台基准采图、二次补偿均适用。已有请求无需新增字段。

如果手眼结束后没有释放保持状态，后续跨机台取图也会保持亮灯；不会因为接口名称不同自动切换模式。因此 Java 应在整组手眼采图结束时调用 `off`。

“未调用开灯接口”可以自动补光；“调用开灯失败或通信超时”不能当作未调用，必须先查询、排查并恢复，不能盲目继续采图或重复开灯。
