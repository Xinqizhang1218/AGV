[handeye_calibrator.py](D:/code/AGV/pkg3_260522/agv_vision/vision/handeye_calibrator.py:19)接口、数据模型和 Java 请求字段均未修改。
### 1. 新增 XY 样本分类
原来没有分类逻辑，所有样本都直接参与 XY 标定。
修改后新增：
```python
XY_DUPLICATE_TOLERANCE_M = 0.0001  # 机器人 XY 相差不超过 0.1 mm 时视为同一位置
@classmethod
def split_samples_by_xy(
    cls,
    samples: list[HandEyeSample],
) -> tuple[list[HandEyeSample], list[HandEyeSample]]:
    """把首次出现的 XY 用于平移标定，重复 XY 仅用于角度标定。"""
    translation_samples: list[HandEyeSample] = []
    angle_only_samples: list[HandEyeSample] = []

    for sample in samples:
        is_duplicate_xy = any(
            math.hypot(
                sample.robot_x_m - previous.robot_x_m,
                sample.robot_y_m - previous.robot_y_m,
            ) <= cls.XY_DUPLICATE_TOLERANCE_M
            for previous in translation_samples
        )

        if is_duplicate_xy:
            angle_only_samples.append(sample)
        else:
            translation_samples.append(sample)

    return translation_samples, angle_only_samples
```
判断公式为：
```python
sqrt((当前X - 历史X)² + (当前Y - 历史Y)²) <= 0.0001 m
```
也就是 XY 总距离不超过 0.1 mm 时，认为位置重复。
### 2. 修改 XY 标定输入
原来：
```python
def solve(
    self,
    samples: list[HandEyeSample],
) -> HandEyeCalibrationResult:

    if len(samples) < 3:
        raise CalibrationError(
            '二维仿射至少需要 3 个样本，建议 9 个以上'
        )

    image_pts = np.array(
        [s.observation.board_center_px for s in samples],
        dtype=np.float64,
    )

    robot_pts = np.array(
        [[s.robot_x_m, s.robot_y_m] for s in samples],
        dtype=np.float64,
    )
```

问题是 `samples` 同时包含平移和纯旋转样本，纯旋转图片也会进入 XY 矩阵计算。

修改后：

```python
def solve(
    self,
    samples: list[HandEyeSample],
) -> HandEyeCalibrationResult:

    translation_samples, angle_only_samples = (
        self.split_samples_by_xy(samples)
    )

    if len(translation_samples) < 3:
        raise CalibrationError(
            '二维仿射至少需要 3 个不同 XY 位置的样本，'
            '建议固定 RZ 采集 9 个以上；'
            f'当前输入 {len(samples)} 个样本，'
            f'只有 {len(translation_samples)} 个不同 XY 位置'
        )

    image_pts = np.array(
        [
            s.observation.board_center_px
            for s in translation_samples
        ],
        dtype=np.float64,
    )

    robot_pts = np.array(
        [
            [s.robot_x_m, s.robot_y_m]
            for s in translation_samples
        ],
        dtype=np.float64,
    )
```

现在只有首次出现的不同 XY 位置参与矩阵求解。

angle_calibration = self.solve_angle_calibration(samples)

修改后：

angle_calibration = self.solve_angle_calibration(

### 4. 修改返回的样本数量

原来：

```python
sample_count=len(samples),
```

它表示接口传入的全部样本数量。

修改后：

```python
sample_count=len(translation_samples),
```

现在它表示真正参与 XY 仿射矩阵计算的不同位置数量。

最终处理关系是：

```text
输入全部样本
    │
    ├─ XY 第一次出现
    │      └─ 参与 XY 仿射矩阵计算
    │
    └─ XY 曾经出现过
           └─ 只参与角度标定
```

修改没有改变手眼矩阵的求解公式，只改变了传给两个求解过程的样本集合，因此属于最小范围修改。




不能说“改完就完全没问题”，但这次修改确实解决了当前最主要的 XY 矩阵被旋转样本压缩的问题。历史数据回放从 `16.1 mm RMSE` 降到了 `0.031 mm`，方向比例也恢复正常。

不过还有这些风险，建议按优先级处理。

### 必须确认

1. 必须重新标定并覆盖旧矩阵

修改代码不会自动修复已经保存的旧手眼矩阵。生产标定接口目前不自动保存矩阵，[app.py](D:/code/AGV/pkg3_260522/agv_vision/api/app.py:738)明确写了：

```python
# 不再 backend.save_handeye()
```

因此需要：

- 重新采集并调用标定接口；
- Java保存新返回的 `matrix2x3`；
- 后续补偿必须传新矩阵；
- 删除或停用旧矩阵。

否则程序仍然会使用原来的错误矩阵。

2. 当前容差实际是0.3 mm，不是注释中的0.1 mm

当前代码 [handeye_calibrator.py](D:/code/AGV/pkg3_260522/agv_vision/vision/handeye_calibrator.py:19)实际为：

```python
XY_DUPLICATE_TOLERANCE_M = 0.0003
```

这代表：

```text
0.0003 m = 0.3 mm
```

但后面的注释仍写0.1 mm。若预期是0.1 mm，应使用：

```python
XY_DUPLICATE_TOLERANCE_M = 0.0001
```

对于20–30 mm的标定步距影响不大，但代码和注释必须统一。

### 高风险点

3. 代码没有检查平移样本的 RZ、Z 是否真的固定

目前只根据 XY 分类：

```python
if XY 重复:
    只算角度
else:
    参与 XY 矩阵
```

假如出现下面的数据：

```text
p01：X=0，Y=0，RZ=0°
p02：X=20 mm，Y=0，RZ=10°
```

`p02` 仍然会参与 XY 标定，旋转还是会污染矩阵。

所以采样阶段必须保证：

```text
参与 XY 标定的所有样本：
Z 固定
RX 固定
RY 固定
RZ 固定
```

更稳妥的后续代码改进，是自动检查平移样本的姿态范围，超限就拒绝标定。

4. 只有样本数量检查，没有检查点是否共线

当前代码只检查：

```python
if len(translation_samples) < 3:
    raise CalibrationError(...)
```

但下面3个点虽然数量够，仍然不能稳定求二维矩阵：

```text
(0, 0)
(20, 0)
(40, 0)
```

因为它们全部在一条直线上。[handeye_calibrator.py](D:/code/AGV/pkg3_260522/agv_vision/vision/handeye_calibrator.py:68)调用 `np.linalg.lstsq()` 时没有检查矩阵秩，可能返回一个看起来正常、实际退化的矩阵。

至少应该检查：

```python
design = np.column_stack([
    image_pts,
    np.ones(len(image_pts)),
])

if np.linalg.matrix_rank(design) < 3:
    raise CalibrationError(
        'XY 标定点共线或分布退化，请使用二维网格重新采样'
    )
```

5. 计算了 RMSE，但不合格也照样返回矩阵

代码计算了误差：

```python
err = np.sqrt(
    np.mean(
        np.sum((pred - robot_pts) ** 2, axis=1)
    )
)
```

但[service.py](D:/code/AGV/pkg3_260522/agv_vision/core/service.py:422)只是记录日志，没有拒绝不合格矩阵。之前 `16.1 mm RMSE` 的矩阵就是这样被正常返回的。

建议至少增加：

```text
RMSE ≤ 0.5 mm：通过
0.5–1.0 mm：警告或重新采集
> 1.0 mm：拒绝使用
```

同时检查两个方向的矩阵比例，不能再次出现相差5倍的情况。

6. 角度标定的 `reliable` 判断不可靠

当前[角度标定代码](D:/code/AGV/pkg3_260522/agv_vision/vision/handeye_calibrator.py:149)只判断：

```python
robot_range = max(robot_values) - min(robot_values)
reliable = robot_range >= 1.0
```

它没有检查 `rmseDeg`。

使用历史数据回放时，出现了：

```text
rmseDeg = 52.24°
reliable = true
```

明显不合理。应该同时判断：

```python
reliable = (
    robot_angle_span >= 10.0
    and best['rmseDeg'] <= 0.5
)
```

此外，Java传入的 `rz` 必须是度。历史数据里有一批值很像毫弧度，如果仍然传毫弧度，角度标定一定错误。

### 运行时风险

7. 机器人角度补偿当前被强制设为0

二次补偿接口在 [app.py](D:/code/AGV/pkg3_260522/agv_vision/api/app.py:931)中写的是：

```python
# 'dthetaRobotDeg': comp.get('dtheta_robot_deg'),
'dthetaRobotDeg': 0.0,
```

也就是说：

- 程序内部虽然计算了角度标定；
- 接口最终却始终给 Java 返回 `0.0`；
- 当前重复 XY 角度样本对实际角度执行没有作用。

如果现在只测试 XY，可以暂时保留；如果AGV需要角度补偿，这里必须恢复。

8. ArUco没有启用亚像素角点优化

[aruco_detector.py](D:/code/AGV/pkg3_260522/agv_vision/vision/aruco_detector.py:17)只创建了默认参数，没有设置：

```python
cornerRefinementMethod = cv2.aruco.CORNER_REFINE_SUBPIX
```

现场数据角度大约以 `0.135°` 为一级跳变。距离旋转中心1 m时，`0.135°` 相当于约 `2.36 mm` 横向变化。

9. `marker_ids`配置没有真正参与过滤

配置中只允许 ID 0，但[aruco_detector.py](D:/code/AGV/pkg3_260522/agv_vision/vision/aruco_detector.py:33)会处理画面中检测到的所有同字典 ArUco。`preferred_origin_id`也只是保存到结果，没有真正选择它。

如果画面中出现其他同字典标签，中心和角度可能被错误平均。
